# Native implementation, completion gates and evidence

Raw artifacts named below are retained locally under the [artifact policy](ARTIFACTS.md); their identities are in the [artifact manifest](local-artifacts.txt). They are excluded from Git.

Updated October 5, 2026. This is the authoritative status of the
[archived fresh-start blueprint](archive/FRESH_START_BLUEPRINT.md). Its bounded stages 0–7 are
implemented: a local native system, comparative experiments, isolated extension
candidates, verified finite code changes and a frozen evidence conversation
interface. Completion covers these declared contracts. It does not establish an
optimal model, Life superiority, fluent conversation or arbitrary coding ability.
The follow-up contract audit found gaps in library-owned source orchestration,
cumulative clock limits and work-capture preflight. They are now covered by
native implementations and regressions; the expanded suite has fifteen tests.
All fifteen pass on each of the three declared toolchains, with warning-free
final builds, strict C11 checks, formatting and targeted static analysis.
The [contract closure evidence](verification/2026-10-05-blueprint-closure/README.md)
records the final integrated checks. Earlier verification and all quality results
remain retained without being reclassified as new quality evidence.
The [subsequent durability review](verification/2026-10-05-contract-durability/README.md)
closes three further audited boundaries: admitted failed-capture receipts survive
CLI exit, full test builds cannot silently omit finite-code integration tests,
and both code workflows retain a frozen parent checkpoint and authentic contact
proof before tools. Measurement receipts bind those identities. Final native
tests and original failed attempts remain separately retained.

Retention follows the [research artifact policy](ARTIFACTS.md). Protocols,
design and report documents are versioned. Historical run outputs, copied source
fixtures, measurements, receipts and snapshots remain local, with committed path,
size and SHA256 identities; a Git clone does not contain those artifacts. Native
build/test fixtures remain versioned in `data/audit`.

These stages implement the blueprint's bounded system and research workflow.
Acceptance of an isolated candidate is a separate outcome from implementing its
gate. A failed experiment does not authorize replacing the default recipe.
The section-13 useful-behavior criterion is met only within the measured scope:
source evidence, scoped byte learning and independently verified finite patches.
The retained sequence and chooser-transfer failures still prevent a broader
reliable-model claim.

The subsequent audit corrected the earlier blanket completion claim at three
implementation boundaries. `c_source_train` now owns the bounded recipe in the
library, selecting at most 32 current TRAIN SOURCE records by immutable ID and
reporting omitted records and partial committed progress. Life preflights the
complete live-plus-retired optimizer-clock sum before publishing a generation;
boundary regressions preserve every state component and consumed receipt. Native
TRAIN work capture rejects reserved evaluation locations and link traversal
before execution or artifact creation, and retains canonical launch/output paths.
Windows case-varied absolute SOURCE aliases refresh only when native file
identities match the scanned ordinary file. This closes concrete implementation
gaps; it does not change the independent quality conclusions below.

## Learning and provenance

The native loop has ingested this repository's actual uncommitted source,
attributed Codex proposals and visible user/work records. Native commands retain
direct argv, working directory, exit status and complete raw output separately
from explicitly bounded context views. Rescans create new immutable versions;
"current" means the latest admitted source version, so edits require a rescan.
The earlier working checkpoint reached 474 contact-owned updates before this
expansion. That is historical coverage evidence, not a current release count or
an additional independent quality measurement.

LLM claims and activity are inputs only. SOURCE byte/EOS targets are checked
against immutable TRAIN records; code labels come from native TRAIN evaluations
bound to exact input, parent, evaluator and receipt identities. DEV/AUDIT cannot
teach or enter retrieval. Raw-byte callers still must declare honest provenance
and splits. Research reports and evaluator answers remain in excluded research
or audit storage.

The default production recipe uses two to four owners and a frozen shared
representation. Alternate schedulers, a single expert and the trained pair-token
comparison are explicitly research references, not production entry points.
Research owners cannot be published as production checkpoints. No global
production recipe has been selected from the opened AUDIT results.

## Retained quality results

The first [source experiment](experiments/2026-10-05-source-quality/report.md)
completed 64 genuine-contact updates. TRAIN loss fell from 5.5494 to 2.0235 and
the independent counted-loop/array-lookup AUDIT loss fell from 5.5481 to 4.3260.
This was one seed and selected next-byte prefixes, with a zero-update frozen
comparator. It establishes scoped learning through Life, not a scheduler
advantage. Its code readout values and moments remained unchanged, although
changing routing can move unrelated head outputs.

The new [comparative experiment](experiments/2026-10-05-comparative-research/report.md)
uses three seeds, ten learned conditions with exactly 96 joint updates each, a
separately identified zero-update comparator and two inference-only ablations.
TRAIN binary search and byte reversal, DEV byte counting and insertion sort, and
AUDIT ring buffer and unsigned GCD are independently authored C families. Every
selected prefix, contiguous causal tail, bounded autoregressive step, EOS and
retention distribution is retained: 19,404 prediction rows and 2,880 exact TRAIN
feature/target rows. Each split has 58 teacher-forced cases per seed/phase; each
rollout phase has six sequences and 102 scheduled targets.

Every condition completes zero exact rollouts out of 18 across the three seeds,
and none predicts EOS at the declared final rollout position. Raw-byte Life gets
22/306 scheduled rollout targets correct; pair subwords get 38/306. Better
teacher-forced loss therefore does not establish reliable sequence generation.

| Comparison | Observed outcome | Interpretation |
| --- | --- | --- |
| Normal Life, frozen physical Life and deterministic scheduling | Their two-owner learned distributions tie exactly. | This experiment finds no Life scheduling advantage. |
| Raw-byte Life versus zero updates | Mean AUDIT loss worsens from 5.5462 to 5.7900 despite TRAIN improvement. | Generalization can regress; the scoped quality gate fails. |
| TRAIN-fitted pair subwords | Mean AUDIT loss falls from 5.5526 to 4.6162 and beats raw-byte Life by 1.1738. | A reversible representation helps this fixture; no production recipe is promoted from this AUDIT result. |
| Four specialists versus two | Mean AUDIT loss improves by 0.0758 against two-owner Life. | Active parameter and owner-update budgets differ, so this is not a matched-total-compute capacity claim. |
| Source plus LLM proposal versus source alone | Mean AUDIT loss improves by 0.0739, meeting this fixture's declared margin. | Attributed context can change quality; this does not establish general semantic usefulness of LLM claims. |
| Source plus activity, or source plus both contexts | Mean AUDIT loss worsens by 0.1042 and 0.2991 respectively against source alone. | Additional context is not automatically beneficial. |

The token dictionary is fitted only on TRAIN bytes and reconstructs all six
sources exactly. Token counts decrease, but canonical two-byte token wires can
use more storage than raw bytes; the report keeps both measures. All six originals
also pass strict C11 syntax checks on Windows clang and Linux GCC, giving 12/12
checks with exact unchanged hashes. Given byte equality, this supports validity
of the reconstructed sources, not validity of model-generated programs.

The [project code suite](experiments/2026-10-05-project-code-suite/report.md)
retains all 12 candidates across checked affine sizing, lower bound and unsigned
saturating addition. Independently verified TRAIN outcomes select actions 3, 1
and 2; all three winners pass DEV and fresh AUDIT gates. The reviewed production
patch replaces a correct linear lower bound with an equivalent binary search,
reducing measured TRAIN comparisons from 49 to 27 while retaining correctness.
The accepted fixed-site patch has been applied to `src/domain/algorithms.c` and
formatted. The [publication receipt](verification/2026-10-05-completion/applied-patch.md)
retains exact parent, accepted winner and formatted-source hashes, manifest/header
checks, rollback source and the successful native apply command.
This measures algorithm work, not elapsed speedup.

Six independently attributed TRAIN receipts improved winner probabilities on
their fitted inputs. However, the frozen independent-use inputs did not improve:
the affine model choice worsened from zero to one AUDIT failure, while lower-bound
and saturation choices retained one and six failures. The verified patch is a
useful local code improvement; the learned chooser does not yet transfer reliably
to rephrased requests. All these distributions were frozen before AUDIT use.
Earlier [range](experiments/2026-10-05-code-trial/report.md) and
[injected-context range](experiments/2026-10-05-context-code-trial/report.md)
trials remain historical scoped evidence; the repeated range catalog is not a
fresh transfer test.

The [evidence session](experiments/2026-10-05-frozen-session/report.md) returns
10/10 exact supported excerpts and 7/7 explicit abstentions across frozen queries,
with paths, spans, versions, hashes and attribution. Original trainer checkpoints
remain byte-identical across inference. This is a bounded source evidence
interface. Full byte-sequence generation has not earned a fluency or general
code-generation gate; generated output is separately labeled experimental and
unverified, with an explicit EOS or byte limit.

## Extension permissions and durability

Shared representation starts as an identity diagonal scale in an isolated fork.
Its explicit later-phase permission requires every live owner to participate in
the physical encounter; shared updates have their own clock and budget. Unused
readout values/moments remain unchanged, and output retention is evaluated.
Cellular policy has separate learning and editing permissions. Its bounded
lookahead teacher reads only world geometry and physical claims, never source
targets, task outcomes or audit answers. Learned edits and an edits-disabled
comparison must report contact changes and downstream behavior independently.

Merge candidates require a real contact between the chosen parents, preserve
other owned slices and retain parent UIDs, new child UID, clocks and contact-world
proof. Schema 3 stores up to 512 retired completed tasks, preserving their exact
targets, causal input, formatter/evidence metadata, receipts and original owner
UIDs. Retention maps those UIDs through merge lineage. Explicit retired TEXT
replay supplies a new live eligibility mask and creates fresh pending tasks;
consumed code receipts are never replayed. Queue/archive saturation fails
explicitly, and failed replay preserves the incumbent.

Schema 1 and 2 remain readable when their canonical state, recipe and build
validate. Missing extension fields receive the declared legacy defaults. A
schema-2 merged checkpoint cannot recover tasks that its older writer discarded;
loading it does not invent a retired archive. Only schema 3 provides the new
durable task-history guarantee. Same-build continuation, including extension
permissions, retired tasks and replay, is verified separately from statistical
quality. The build identity names compiler/version and processor; it is not a
cryptographic identity of every source or executable byte.

The [instrumented extension rerun](experiments/2026-10-05-gated-extensions-v2/report.md)
retains every fixed candidate, complete probabilities and features, per-split
denominators, actual source-update budgets, policy/inspection/lookahead costs,
contact changes and parent/reference checkpoints. It reuses the same opened
families and seeds as the [initial report](experiments/2026-10-05-gated-extensions/report.md);
it adds durability and inspection evidence rather than a fresh transfer result.
The policy control still fits its world-only learner with editing disabled.
Shared-scale and world-policy candidates each pass two of three seed gates;
merging passes one of three. These mixed results do not authorize a global recipe.

Merging reduces canonical model bytes from 805,720 to 604,488 and whole checkpoint
bytes from 831,137 to 631,185 while retaining 32 archived tasks. Fixed model
allocation remains 805,728 bytes, so this is a serialized-storage benefit, not a
RAM reduction. Policy interventions change subsequent contact masks in all
three seeds; downstream retention rejects one of those seeds. Published-world
traces explicitly record when fixed reseeding overrides a proposed edit. No
global merge, shared scale or cellular policy is selected merely because one
AUDIT seed passes.

## What remains outside this bounded completion

The system is not a general conversational or autonomous coding model. Larger
representations, hierarchical BPE, broad generated patches, arbitrary LLM patch
execution, learned merge selection, parallel kernels and larger task corpora need
new protocols and independent quality/retention/resource gates. The negative
sequence and chooser-transfer results justify keeping those expansions gated.
These are future capability extensions, not silently unfinished components of
the declared native bounded release. Primary sources and assumptions are retained
in [REFERENCES.md](REFERENCES.md).
