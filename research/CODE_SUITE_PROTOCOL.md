# Three-domain native code suite protocol

Registered before this suite's first execution. October 5, 2026.

The authored catalogs cover checked affine size arithmetic, lower-bound lookup,
and unsigned saturating addition. Four whole C modules per catalog are compiled
with strict C11 and warnings treated as errors. Compiler and evaluator raw logs,
every case and every candidate remain in a new immutable directory. Failed builds
defer learning. Correct action IDs vary across domains.

TRAIN has two independently authored families per domain. Aggregate TRAIN
targets minimize failures, then exact lower-bound comparison count, then action
ID. Each family provides one receipt supporting that selected TRAIN action,
bound to its exact parent, frozen context, evaluator and raw measurement.
Production fitting is exclusively through authentic Life contacts.
DEV and AUDIT cannot provide targets, enter retrieval, or select candidates.
Fresh AUDIT families use separately authored overflow boundaries, duplicate/empty
arrays, and near-maximum arithmetic; they are distinct from the prior range trial.
This is scoped transfer across these authored case families, not arbitrary code.

Input freezing preserves supported SOURCE, LLM_PROPOSAL and ACTIVITY bytes with
IDs, versions, full paths, attribution and digests. Unsupported roles abstain.
The complete input must fit 64 KiB or fail explicitly. A mistaken LLM suggestion
remains context and cannot override the independent measurement.

Publication requires zero DEV and AUDIT failures for all chosen actions. The
real project patch is a correct linear lower-bound implementation replaced by an
equivalent binary implementation, with strictly fewer TRAIN comparisons and no
correctness regression. Checked size arithmetic and saturation remain correct
production APIs; their separate defective fixture catalogs establish repair
evidence without adding broken production behavior. The reviewed full-module
winner changes only the declared `src/domain/algorithms.c` lower-bound site.

Explicit `c_patch_apply` is separate from training. It accepts only this fixed
target, exact expected parent, known catalog module and complete accepted bundle.
It checks raw evaluation identities and success, rejects symlink/reparse ancestors,
retains the exact parent for rollback and publishes atomically. It never invokes
tools, infers approval from a proposal or changes model parameters. Failure leaves
the project source unchanged. Timing is observational; comparison counts measure
algorithm work, not peak memory or elapsed speedup. Every report includes all
domains, denominators, probability changes, actual contact/update counts and scope.
