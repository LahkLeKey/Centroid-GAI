# M5 bounded learned strategy result

The registered native trial passed on October 5, 2026. The feature recommends
one of four independently checked implementations of the existing repository
`c_lower_bound` contract. This is useful within the registered sorted-array
workload profile: learned selection reduced value comparisons on fresh DEV and
AUDIT workloads. It does not generate source or establish general coding or
LLM improvement. Selection belongs outside the host's search hot path; the
comparison reduction is not a net wall-clock search speed claim.

The [protocol](M5_PROTOCOL.md) was frozen before workload construction or
evaluation. Fresh TRAIN families were affine and paired-duplicate arrays; DEV
used extra-gap and triple-duplicate arrays; AUDIT used cyclic-gap and
periodic-repeat arrays. Each split contained 40 complete arrays/keys, with five
requested workloads in each of eight regions. No teacher output was an input.
Two bytes derived only from count, key and endpoints were encoded by the native
byte-position projection. Only actual source and independently measured TRAIN
records entered trainer context. The native generator lives in excluded
`tests/sdk_qualify.c`; opened holdout artifacts remain in excluded research.

All three Life seeds met every registered quality gate: zero semantic failures,
49.26% fewer AUDIT comparisons than production binary search, 16.33% fewer than
the endpoint heuristic, and more than 10% fewer than each seed's zero-update
model. The frozen-model AUDIT totals were 23,250, 37,538 and 360 respectively.
All TRAIN targets came from complete native candidate measurements and a
separate linear correctness oracle. Action 0 was additionally checked against
the actual compiled production function, including its exact comparison count.

Each trained condition consumed 480 unique measurement receipts, made 480 joint
updates and 960 owner updates, and finished at owner clocks 480/480. Every
production update had an independently recorded physical B3/S23 contact graph
and complete pre-update world. Shared and policy clocks stayed zero. TEXT
readout values and Adam moments remained bitwise unchanged. Mean TEXT cross
entropy changes on eight fixed source-bound probes were -0.01333144,
-0.00969077 and +0.00045523, within the +0.05 gate.

The three training schedules tied exactly. Their common update order, examples
and fixed fitting budget make this a bounded learned-feature result with
Life-authorized production updates. They provide no evidence that Life improves
quality over these alternative schedules. Observation bands repeat across
splits; the measured transfer is to new array constructions within the declared
profile rather than unseen input semantics. The endpoint heuristic is one
registered comparator, not every possible handcrafted dispatch table.

The first fresh run took 3.543 seconds and used a measured 33,267,712-byte process
peak. After opening AUDIT, two native repetitions checked deployment and artifact
contracts without changing families, targets, fitting recipe, selection or
quality gates. These are conformance repetitions, not new independent AUDIT.
The final private conformance run took 3.805 seconds, used 34,709,504 peak bytes,
and averaged 34.280 microseconds over 240 portable model-validation,
observation and inference calls. Portable CODE scores agreed with their trainer
within 1e-12. This includes endpoint encoding and full value validation; it still
does not include a host's application policy or constitute net search speedup.

The measurement host was Windows x86-64 using clang 21.1.0, strict C11 and `-O2`.
Its reported processor identity was Intel64 Family 6 Model 151 Stepping 5,
GenuineIntel, with 12 logical processors. These measurements are a recorded
machine-specific envelope, not a promise for every supported CPU. Cross-toolchain
and installed-consumer checks belong to the product release evidence.
